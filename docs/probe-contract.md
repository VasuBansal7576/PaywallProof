# Shared scenario collection contract

`packages/evidence/src/probe.ts` exports `observeScenario(options)`. Both original and repaired targets use this same trusted orchestration, with unchanged policy and evidence evaluation. The target cannot replace this module.

Options are `scenarioId`, `policy`, `billing`, `collect`, and optional trusted `assertActive`, `now`, and `wait` callbacks. `scenarioId` is SC01 through SC04; `policy` is a validated AccessPolicy. `billing()` returns a Billing snapshot. `collect(notBefore)` returns an EvidenceEvaluation from actual provider, application, API and browser observations. `assertActive()` throws when authorization or the deadline no longer permits work. `now()` returns Unix milliseconds and defaults to Date.now; `wait(milliseconds)` defaults to a real asynchronous timer. Injected clocks are only a test boundary, never input accepted from the model or HTTP.

Provider confirmation comes first. SC01 requires confirmed no subscription. SC02 requires active, initially paid and not scheduled to cancel. SC03 requires active, initially paid, scheduled cancellation and billing time before the period end. SC04 requires canceled with billing time at or after period end. Unestablished provider snapshots and temporarily rejected provider reads are polled once per second for at most 90 seconds. A final read error rejects with PROVIDER_UNAVAILABLE; an unestablished snapshot at the bound rejects with SYNC_TIMEOUT. No feature collection occurs before provider state is established.

Provider confirmation at exactly 90,000 real milliseconds is allowed. Confirmation after that bound rejects with `SYNC_TIMEOUT` even if the returned snapshot is established. At the bound, an unestablished snapshot rejects with `SYNC_TIMEOUT`, while a rejected provider read rejects with `PROVIDER_UNAVAILABLE`. These are Error objects with the corresponding `code`. Authorization exceptions propagate unchanged and are not provider read failures.

The original policy's full synchronization window starts when provider state is confirmed. Collection uses that confirmation time as its earliest allowed observation time. All three verdicts must pass for an early success. Failed, inconclusive, skipped, or unsupported results do not end the window early.

At or after the synchronization boundary, collect two additional independent evidence sets, both requiring observation times at or after that boundary. A failure is retained only if both post-boundary evaluations fail for the same reason in that channel. A second-set failure with a different first-set verdict or code becomes inconclusive with UNSTABLE_CONTRADICTION. API, browser and state are compared independently. The final result includes the references from both post-boundary collections. A pass or inconclusive in the second set is never promoted to a failure.

The returned value has the same EvidenceEvaluation shape as collection results: `{api,browser,state,observationIds}`. Each channel has `{verdict,code}` and the verdict enum is `pass`, `fail`, `inconclusive`, `unsupported`, or `skipped`. Non-failure verdicts and their codes from the second post-boundary set remain unchanged, including `unsupported` and `skipped`. Feature collection cadence within the window is not prescribed; tests may inject deterministic waits but must not require a particular backoff schedule.

Authorization is checked before provider polling and every collection, including each of the two post-boundary collections, and after the final collection before returning. `assertActive` may return `void` or `Promise<void>`; every check is awaited before work proceeds. A synchronous throw or asynchronous rejection aborts immediately, propagates unchanged, and cannot be swallowed as a provider read error. Collection exceptions propagate; the orchestration does not turn transport errors into access failures. It does not change the approved policy or rewrite an earlier observation.
