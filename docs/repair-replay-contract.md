# Frozen repair replay contract

The trusted host owns `packages/repair/src/oracle.ts`. Its code and test evaluator are never transferred into writable target files. No function in this module calls the Stripe API.

`createRepairReplayPlan({runId,targetBuild,policy,observations})` accepts the original run identity, its exact target build, its immutable validated AccessPolicy, and recorded Observation values as defined in the evidence contract. It returns a detached plan with schemaVersion1, mode `local_replay`, a fresh UUID runId, the original policyHash, fresh UUID free/paid fixture markers, and `states` with Billing values for SC01 through SC04.

The exact plan shape is `{schemaVersion:1,mode:'local_replay',runId,policyHash,markers:{free,paid},states:{SC01,SC02,SC03,SC04}}`.

For each scenario, select the latest observation by observedAt among source `stripe` records matching the original run, target build and policy hash. Verify its payload SHA256. A missing or corrupt selected record cannot be replaced with invented provider evidence. Every selected state must be test mode with resolved identity and the configured price. SC01 must confirm no subscription and null customer/subscription. SC02 requires initially paid active access without scheduled cancellation. SC03 requires initially paid active access, scheduled cancellation, and billing time before period end. SC04 requires canceled at or after period end. All paid scenarios must refer to the same original customer, subscription, period end and execution mode. Contradictions, missing evidence and invalid policy reject; a module RepairError uses code REPAIR_BILLING_EVIDENCE_REQUIRED for missing or contradictory evidence.

All four selected observations use the same execution mode. The free subject differs from the paid subject; all paid scenarios use the same subject. At the latest observedAt tie, identical payloads and scope metadata are permitted, but conflicting newest observations reject with `REPAIR_BILLING_EVIDENCE_REQUIRED`. SC04 may have `initialInvoicePaid:false`; canceled-state denial does not require initial payment, and replay preserves that recorded fact. Synthetic fixtures may use the public EvidenceStore.record result to obtain an honest payload digest without assuming a serialization algorithm.

The output replaces customer and subscription IDs with fresh synthetic IDs beginning `cus_replay_` and `sub_replay_`. The paid states share those IDs. Other billing facts and times come from the recorded states. It preserves the original policy hash and does not mutate input observations. Creating another plan produces a separate synthetic run, customer, subscription and markers. Baseline and patched targets must use the same persisted plan, not call this function again between executions.

`replayPayload(plan,scenarioId)` accepts SC02, SC03 or SC04 and returns deterministic JSON text. The event is explicitly test mode with a synthetic event ID, subscription metadata containing the synthetic plan runId, and subscription data from that plan's corresponding state. Event types are customer.subscription.created, customer.subscription.updated and customer.subscription.deleted respectively. The event contains the configured price and period end and an expanded test invoice linked to that same synthetic customer and subscription. Invoice status is paid only if the recorded initialInvoicePaid fact is true. No private key, customer email, original customer ID or original subscription ID is included. Repeated calls with the same plan and scenario produce byte-identical event payloads. Signing occurs separately with each disposable target's secret.

The event envelope is `{id,object:'event',type,livemode:false,created,data:{object:subscription}}`, where `created` is that state's `subscription.billingTime`. Subscription fields are `{id,object:'subscription',livemode:false,customer,metadata:{runId},status,cancel_at_period_end,items:{data:[{price:{id,livemode:false},current_period_end}],has_more:false},latest_invoice:{id,object:'invoice',livemode:false,status:'paid'|'open',customer,billing_reason:'subscription_create',parent:{subscription_details:{subscription}}}}`. IDs are synthetic; callers must not depend on event-ID spelling or JSON whitespace. Invoice status is `open` when the recorded initial payment fact is false.

`runRepairOracle` is integration-only. It creates fresh users on an actual isolated target, sends the frozen events through its real signed replay handler and collects all four scenarios with the same `observeScenario` and `observeFeature` used by the original run. Browser results require actual Playwright execution and screenshots. It returns mode, planHash, scenarios, recorded observations, artifacts, cleanup receipts and completedAt. Fixture cleanup is attempted on success and failure. Missing browser or transport evidence must stay inconclusive; passing API responses cannot stand in for browser results. Returned local replay evidence never proves Stripe delivery or a real Stripe lifecycle.

`oracleFingerprint(repositoryRoot)` hashes the trusted policy, evidence, scenario orchestration, network, browser and frozen replay modules. The controller records that binding when the original run starts and rejects a repair if it changes. A source change requires an original rerun, not a substituted oracle hash.
