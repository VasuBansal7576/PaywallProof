# Authoritative evidence boundary

Independent test input specification. Do not read implementation when authoring tests.

`packages/evidence/src/index.ts` exports `EvidenceStore`, `evaluateEvidence`, and `redact`.

Construct `new EvidenceStore(databasePath, secrets?)` using a real temporary SQLite path. `record(input)` accepts `{runId,scenarioId,subjectId,source,policyHash,targetBuild,observedAt,billingTime,mode,payload}`. scenarioId is SC01..SC04, source is stripe/application/api_probe/browser, mode is stripe_sandbox/local_replay. observedAt is real Unix milliseconds, billingTime is Unix seconds or null. Payload is finite plain JSON, nesting maximum32. Other fields reject unknowns. `record` returns same fields with generated id and sha256 of stored redacted payload. `get(id)` returns the persisted record and verifies hash, `list(runId)` returns only that run's observations, `close` closes storage. Caller mutations to returned records must never change stored evidence. Never overwrite an existing observation. These methods are trusted collectors only; no public HTTP/MCP write-evidence method exists.

`redact(value,secrets=[])` returns a detached JSON tree. Redact values under authorization, cookie, set-cookie, password, secret, token, apiKey/api_key, webhookSecret/webhook_secret, email, access_token, refresh_token keys case-insensitively. Redact Stripe test/live keys, webhook secrets, GitHub tokens, Bearer/Basic credentials and emails within arbitrary strings. Also redact every nonempty literal supplied in secrets from both string values and property names. Do not modify the input. Synthetic canary tests must never use real credentials.

`evaluateEvidence(store,input)` accepts `{runId,scenarioId,subjectId,policy,targetBuild,mode,fixtureMarker,stripeId,applicationId,apiId,browserId,now,notBefore}`. It loads all four distinct IDs from the authoritative store, never replacement payloads. policy is the immutable policy from public-contracts.md. Reject unknown input fields. Missing evidence produces all inconclusive, never throws a successful assertion. Wrong source, run, scenario, user, policy hash, mode, or build cannot pass or fail access. Observations must be no earlier than notBefore, no later than now, and within 10000 real milliseconds of now. Wrong/missing/stale observations produce all inconclusive.

Stripe payload is Billing from public-contracts.md. API and browser payloads both follow the pure probe contract. Browser payload represents the actual UI action result, not an invented API duplicate. Application payload minimally contains `{principalId,runId,customerId,status,buildId}`. Free status is 'none'; otherwise status follows Stripe. Identity and build must match the run and Stripe customer. Missing/malformed application identity is not sufficient evidence and must make all outputs inconclusive. Unsupported billing expectation makes all outputs inconclusive.

Returns `{api:{verdict,code},browser:{verdict,code},state:{verdict,code},observationIds}`. API/browser use pure evaluation from public-contracts.md. Correct app status gives state pass; a valid mismatched status gives state fail with code STATE_DRIFT. State drift alone must never become an API access-leak claim. A single-cycle fail here is only a candidate; the controller must repeat after the synchronization deadline before persisting an authoritative failure. Test this boundary independently from repeated-cycle controller requirements.
