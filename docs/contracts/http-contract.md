# Product UI API contract

All paths are same-origin `/api`. Next proxies to the private worker. JSON requests. Mutation requests after login must include `X-CSRF-Token` from `/api/session` and `X-Request-Id` generated once per user action, reused only to retry the identical action. Cookies are HttpOnly. No secrets enter chat, report, model prompts, or source.

Errors are JSON `{error:{code,message}}`; non-2xx must be displayed, never converted to a successful state.

- POST /api/login `{token}` => `{csrfToken}` plus session cookie. The operator token is in ignored `.local/operator-token`, configured by local launcher. No seeded account or password. GET /api/session => `{csrfToken}` or 401.
- GET /api/config => `{target:{id,origin}, repository, defaultRef, reviewSkill:{repository,ref}, polarConfigured:boolean, priceId:string, model:string, limits, coverageLimits:string[]}`. `reviewSkill` identifies the Git repository and immutable commit that TrueForge mounts for post-run evidence review. The target ID and origin come from server configuration. Missing Polar credentials is explicit, not a validation pass.
- GET /api/projects => project array.
- POST /api/projects `{name,repository,ref,targetId,targetOrigin,modelConsentModel,ownershipConfirmed:true,modelConsent:true}` => the same fields plus `id`. Repository, ref, target ID, target origin, and consented model must exactly match server configuration. The approval screen reads the persisted origin and model rather than mutable live config. A project saved before either binding existed remains readable with `targetOrigin:null` or `modelConsentModel:null`, but preflight, new runs, repair, and evidence review reject it until the owner reconnects and consents.
- POST /api/projects/:id/preflight `{mode:'polar_sandbox'|'local_replay'}` => `{ready:boolean,adapter,connections}`. `adapter` is the deterministic Adapter Doctor report. `ready` can be true only for a compatible schema-v2 report and passing connections. That report contains the validated target description, `featureConfigHash`, the resolved code-owned feature-probe contract, and `featureProbeHash`; a blocked report has no bindable receipt. The parser retains sound schema-v1 reports for historical reads, but they cannot create a policy or run. `local_replay` is synthetic signed event replay against the actual target. It does not verify Polar.
- POST /api/projects/:id/policies accepts createPolicy input from public-contracts.md. Returns an immutable policy. The UI binds `featureId` and `featureConfigHash` from the compatible Adapter Doctor receipt, uses predicateVersion `paywallproof-entitlement-v1`, schemaVersion 2, cancellation `allow_until_period_end`, `requireInitialPaymentConfirmed: true`, and the configured price ID. GET /api/projects/:id/policies => policy array.
- POST /api/runs `{projectId,policyHash,mode}` => run record. The server rechecks prerequisites before creation. Unready runs return 422 with blockers. GET /api/runs => run list.
- GET /api/runs/:id => `{run,runtime,runtimeError,runtimeCancelError,stopError,operationReconciliation,continuationReconciliation,artifacts,scenarios,observations,cleanup,repairs,repairSupported,evidenceReview,coverageLimits}`. run fields follow control-contract. Every new run persists the exact Adapter Doctor-validated `targetFeature` and `featureProbeHash`; a legacy run may omit either field. The UI must reproduce from that descriptor and must not invent reference-target routes or selectors for a legacy record. `repairSupported` is computed for this saved run and is false unless its repository, ref, target ID, target origin, consented model, and the current worker all match the trusted reference repair profile. Runtime is nullable; otherwise it contains `{sessionId,turnId,lastSequenceNumber,status,error?,pendingApprovals?}`, where `status:'waiting_external'` means a Polar checkout exists and the same TrueForge session is durably paused. `operationReconciliation` records unresolved external operation IDs and whether cleanup is safe or manual review is required. `continuationReconciliation` records plan and checkout continuation lookup results as `reconciled` or `unknown`; an unknown continuation is never resent automatically. Neither receipt rewrites an unknown effect as success. Scenarios are `{id,api:{verdict,code},browser:{verdict,code},state:{verdict,code},observationIds}`; empty means untested. `artifacts` contains the run's browser evidence metadata. Cleanup is the latest receipt per resource, never an append-only history. Observations contain metadata and redacted payloads only. Runtime errors do not mean a passing run. Poll read endpoints only; never create a run or turn on reconnect.
- GET /api/runs/:id/events?after=N => `{events:[{sequence,type,payload,occurredAt}],cursor}`. Resumable durable event batch. UI may poll. Streaming transport can be added without changing replay semantics.
- POST /api/runs/:id/approvals/:approvalId `{decision:'allow'|'deny',bindingHash}` => run record. Display the whole plan, mode, target, policy, fixed object limits, exact consented processing model, expiry, and cleanup permission before decision. The immutable server-side binding also includes a canonical digest of the explicitly configured Polar test mailbox without exposing that address through this API. The controller persists the exact owner decision before changing the run, persists `dispatched` before runtime continuation, and reconciles an uncertain continuation by read only; it never guesses that an absent continuation was not sent. A synchronous deadline gate runs immediately before every fresh continuation and recovery resume; a zero-delay timer is not authorization. If TrueForge has not reached the matching runtime tool approval yet, return 409 RUNTIME_APPROVAL_PENDING; button can retry explicitly. Denial revokes the run MCP capability once the continuation is durably reconciled. Never imply owner approval auto-authorizes PR publication.
- POST /api/runs/:id/cancel `{}` => run record. Explain in-flight actions can finish; no further scenario begins. When a resource-changing operation has an unknown external outcome, the run remains `stopping`, the project lock remains held, and the UI removes the ineffective retry control. The operator must use authoritative target/provider records keyed by the saved run metadata to reconcile and clean the owned effect; this release never turns an attestation into an automatic success receipt.
- GET /api/runs/:id/checkout requires the normal operator session and an active Polar run. It returns a 303 redirect to the validated sandbox checkout URL with `Referrer-Policy: no-referrer`, or 409 while checkout is not ready. The private URL is never included in reports, model tool results, or evidence.
- POST /api/runs/:id/checkout/continue `{}` first revalidates the approved project, target description, and probe-contract binding, then confirms the checkout through an independent provider read. It returns 409 while Polar has not confirmed payment. Once confirmed, it resumes the same persisted TrueForge session with the exact `change_test_subscription` confirmation action. Repeated confirmations are idempotent. Recovery never resumes a legacy or drifted lifecycle session; the saved report and explicit cleanup path remain available.
- POST /api/runs/:id/cleanup `{}` retries unresolved cleanup for an owner-approved terminal run. It revalidates the exact cleanup destinations, starts one fresh two-minute attempt under a per-run lock, and replaces each resource's prior receipt with `deleted`, `retained`, or `leftover`. Each target deletion has a durable per-resource dispatch intent. Neither automatic recovery nor an operator retry resends a dispatched-only deletion without read-only reconciliation; it remains `CLEANUP_OUTCOME_UNKNOWN`. The UI offers retry only when another leftover is safely retryable and labels an unknown delete outcome for manual reconciliation. The route can retry other known leftovers, but cannot change the run outcome, recreate lifecycle resources, or use the MCP logical-operation slot.
- POST /api/runs/:id/evidence-review `{retryCompleted?:boolean}` starts a separate skill-backed TrueForge session only when the current model exactly matches the saved processing consent. The worker mounts the configured `reviewSkill` commit reported by `/api/config`, grants only the two evidence-review tools, and enables two dynamic subagents. `retryCompleted:true` preserves the prior completed attempt before a reviewer-version or stale-report retry. A completed receipt exposes `reportCurrent`; cleanup or any other projected report change makes the old receipt visibly stale, and a default start rejects it until the operator explicitly requests a retry. Startup recovery reattaches one watcher to a running review when processing consent still matches. It cancels the session when consent changed or when startup stopped before a turn was recorded. Report-hash checks on the scoped tools prevent a recovered session from reading or recording against changed evidence. The review can only read the compact bound projection and record two reviewer results; it cannot alter the run outcome. The projected run includes the recorded feature, project, and cleanup hashes, using explicit `null` for legacy records, plus hashed descriptor fields and deterministic match flags. Target-controlled route and selector strings do not enter the model projection.
- POST /api/runs/:id/repairs `{}` => repair state or typed unmet prerequisite error. The configured model must exactly match the project's persisted processing consent before source or observations are read. A target outside the trusted reference repair profile returns `REPAIR_TARGET_UNSUPPORTED` before source or model work begins. Actual repair exposes the diff, test evidence, exact publication approval, and local replay limitation; it never implies unavailable work succeeded.
- GET /api/runs/:id/report?format=json|markdown => downloadable report with real scenario coverage, evidence refs, versions, immutable policy, cleanup, repairs, limitations. Reports escape untrusted content when rendered.

Initial UI must show honest empty states, distinct Untested/Inconclusive/Blocked, sidebar project/run navigation, local-replay warning, and accessible keyboard controls. No fake projects, stats, results, findings or repair diffs. The complete required screens remain in PRD; implement controls for actual endpoints only and disclose blocked operations.

When the configured repository or commit differs from a saved project, the UI explains the mismatch and links to connecting the current configuration. Saved projects, reports and approvals retain their original bindings. The server rejects preflight with `PROJECT_CONFIG_CHANGED`; the UI does not silently migrate or reapprove the project.

Refreshing the configured connection remounts project setup and clears mode/preflight state. Returning to the previous configuration still requires a new explicit check. Run and policy actions also reject an already mismatched project locally; server-side validation remains authoritative.

The workspace searches and filters every returned run without truncating history. Ordering is descending `createdAt`, with ID as a stable tie-breaker. Run tabs use URL fragments and do not issue mutations when selected, reloaded or navigated with browser history. Copy controls expose exact saved IDs or JSON; report links use the authenticated routes above. Mobile navigation keeps the same projects and runs available.

Handled preflight errors are persisted by the existing idempotency middleware after Hono's error handler returns. Repeating the same request ID and body returns the recorded status/body without dispatching another preflight. Regression tests exercise invalid JSON, invalid mode, missing project and a thrown read failure. These known failures are distinct from a genuinely uncertain interrupted mutation, whose pending record must still block blind redispatch.
