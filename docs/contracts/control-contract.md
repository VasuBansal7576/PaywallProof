# Durable control contract

Written before implementation. Independent authors may read this contract and PRD.md, never implementation or other agents' solutions.

`src/run/index.ts` exports `openRunStore({path, clock?})`. It opens a real SQLite file; `clock` optionally supplies Unix milliseconds for deterministic deadline tests. Return methods below. `close()` closes the database. All public methods validate unknown input, reject unknown fields and return detached records. Timestamps and lease durations are safe integers. String identifiers are nonempty and unpadded. Policies follow public-contracts.md and must have a valid hash. Stored records survive close/reopen.

`createRun({projectId,policy,targetBuild,featureConfigHash,targetFeature?,mode})` accepts `polar_sandbox | local_replay`; feature hash must match policy. `targetFeature`, when supplied, is the strict contract-v1 feature descriptor, its hash must equal `featureConfigHash`, and its ID must equal `policy.featureId`. It is part of the immutable approval binding. It remains optional only so records created before descriptor persistence can be reopened. The product controller always supplies the Adapter Doctor-validated descriptor for a new run. Returns `{id, projectId, policy,targetBuild,featureConfigHash,targetFeature?,mode,status:'awaiting_plan_approval',outcome:null,approval:{id,bindingHash,expiresAt,decision:'pending'}}`. The immutable binding includes the full configuration, scenario list SC01..SC04, and fixed limits of two users, one customer/checkout/subscription, 100 tool operations, 15 active minutes. Exactly one active run per project, enforced transactionally across connections. A conflicting run throws a typed error with `code:'ACTIVE_RUN_CONFLICT'`. No external writes occur in this store.

The product controller additionally supplies optional `projectConfigHash`, a SHA-256 binding of the server-configured repository, ref, target origin, Polar organization/product/price, model connection, and repair profile. If supplied, it is included in the immutable plan binding. The product requires it and rejects changed configuration before approval or dispatch. A separate `requestStop(runId)` changes an active run to `stopping` while retaining its project lock. The controller calls `cancelRun` only after in-flight work is accounted for. This does not change the direct `cancelRun` contract below.

`getRun(runId)` returns its persisted record or throws NOT_FOUND. `decidePlan({runId,approvalId,bindingHash,decision:'allow'|'deny'})` requires the exact pending approval, matching binding, and current time strictly before 15-minute expiry. Allow changes status to running, deny to canceled. Repeating the exact same valid recorded decision returns the original result even after expiry; changing the decision throws APPROVAL_CONFLICT. Invalid binding or expiry throws APPROVAL_STALE, without consuming the approval. Denied plans cannot execute operations.

`claimOperation({runId,operationId,kind,args,approvalId,leaseMs})` accepts kind `prepare_fixture | change_test_subscription | await_period_end | probe_feature | cleanup_run`. args is a JSON object, rejecting accessors, cycles, classes, undefined/nonfinite values; maximum nesting32. leaseMs is integer 1..30000. Running + matching allowed plan required. Returns `{kind:'dispatch'|'confirmed'|'unknown'|'in_flight',operation}`. The operation includes operationId,runId,kind,argsHash,state,idempotencyKey,receipt. A new claim persists state dispatched BEFORE returning dispatch. Same ID and arguments while lease valid returns in_flight. Expired lease returns unknown and must never redispatch automatically. Confirmed returns its original receipt. Changed arguments OR kind for the same ID throw OPERATION_CONFLICT. Another run's operation ID must never expose its receipt or permit mutation. Use OWNERSHIP_MISMATCH for a cross-run operation ID. Stable idempotencyKey survives reopen. Active execution deadline is 15 minutes after plan approval, checked before new claims. At most 100 unique operations, retries do not increment. After stop, claims for new operations are rejected, including cleanup until cleanup has an explicit separate safe controller path.

An authenticated Polar checkout can place the runtime in `waiting_external`. The controller records one external-wait credit per persisted wait key and adds only that measured interval to the active execution deadline, capped at 24 hours. The credit is exactly-once across restarts. No ordinary runtime, model, or provider latency receives this exemption.

`confirmOperation({runId,operationId,receipt})` accepts JSON receipt only for a matching dispatched or unknown operation. First confirmation persists receipt. Repeated identical confirmation is idempotent. Conflicting receipt throws OPERATION_CONFLICT; foreign run throws OWNERSHIP_MISMATCH. This can confirm an in-flight operation after cancellation, so its external effect is accounted for. No new dispatch is permitted after stop.

`cancelRun(runId)` records canceled, does not erase operations, releases the active-project lock, and is idempotent. A completed run stays completed. `finishRun({runId,verdicts})` accepts a running run and an array of verdicts defined in public-contracts.md; stores completed + aggregate outcome. This method is internal trusted-controller only, never an HTTP/model outcome setter. Empty verdicts are inconclusive. A completed run cannot be overwritten with different results. Terminal runs are immutable except confirmations of already dispatched effects, cleanup and linked repairs.

`events({runId,after})` returns append-only events with strictly increasing integer sequence, type, payload, occurredAt. after is a nonnegative safe integer, exclusive, supports reload without writes. All state transitions and first operation confirmations append events; duplicate decisions and receipts do not create duplicate state-transition events. Unknown run throws NOT_FOUND.

Failures are Error instances with a nonempty `code`; validation failures use INVALID_INPUT. Methods do not expose tokens or create external resources. Evidence validation and approval of repair publication will have separate contracts before testing.
