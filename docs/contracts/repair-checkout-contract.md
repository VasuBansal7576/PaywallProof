# Repair source and dependency collection

`src/repair/checkout.ts` exports `readRepairSource`, `collectRepairDependencies`, and `REFERENCE_REPAIR_PATHS`. These trusted host collectors read bytes only. They never execute repository scripts, install dependencies, check out code, or contact a network provider.

`readRepairSource({repositoryRoot,baseCommit,repository,paths?})` reads raw Git blobs at an exact lowercase 40-character commit. `repository` is an exact GitHub owner/name. The checkout's origin must be that repository using HTTPS or GitHub SSH form. Paths default to the reference target source allowlist; caller-supplied paths must satisfy the repair path policy. Duplicate paths, symlinks, executable files, submodules, directories, missing paths, non-UTF-8 blobs, and files larger than1MiB are rejected. Uncommitted working-file changes must not affect returned bytes. No working file is overwritten. Return `{baseCommit,repository,files,bindings}`, with files `{path,bytes:Uint8Array,role:'source'}` and bindings `{path,sha256,size}` computed from the actual Git bytes.

`collectRepairDependencies(repositoryRoot,names?)` collects only already-installed packages beneath the real node_modules root. It follows package-manager package links only when resolving a package; links inside a package's file tree are rejected. It reads dependencies and installed optional dependencies recursively, preserving each nested package resolution and package name/version. Exact-version cycles resolve through ancestors. Missing required dependencies fail. Missing optional dependencies may be omitted. No package lifecycle runs. Directory entries named tests, test, **tests**, docs, examples, coverage, benchmark or benchmarks, hidden entries, source maps and Markdown files are excluded. JavaScript, native binaries, package metadata and TypeScript declarations remain available. Return `{files,versions,totalBytes}` with dependency roles and package metadata `{name,version,destination}`. Extracted bytes are bounded at512MiB and20,000 files; symlink escapes, nonregular files, changed sizes and conflicting destinations fail.

These are packaging checks, not a sandbox test or proof that installed code is trustworthy. Actual compilation and execution happen only inside TrueForge's sandbox. Source provenance and dependency versions remain visible in repair evidence; an unsupported package layout must not be reported as a successful repair.

Accepted origin strings are exactly `https://github.com/<owner>/<repo>`, the same with `.git`, and `git@github.com:<owner>/<repo>.git`. Other SSH URL forms are not accepted. The base must name a commit object, not a tree/blob or an abbreviated revision. Source blobs containing NUL or invalid UTF-8 are rejected; an empty UTF-8 source file is permitted.

Dependency entries are `{path,bytes:Uint8Array,role:'dependency'}`. The top-level package destination is `node_modules/<name>` and its files extend that exact prefix. A required nested dependency has destination `<parent destination>/node_modules/<name>` with its installed version. An exact name/version already present in the current ancestor chain may be resolved there instead of duplicated. Version entries are `{name,version,destination}`. Peers resolve from included ancestor/top-level packages; this collector does not install missing peers. Default top-level names are `next`, `react`, `react-dom`, `hono`, `zod`, `standardwebhooks`, `better-sqlite3`, `typescript`, `@types/react`, and `@types/node`.

Package links may resolve into a pnpm-style `.pnpm` store beneath the real node_modules root. A package link resolving outside that root fails, including an otherwise valid package fixture. Ordinary package files must be regular files; package-internal symlinks are not dereferenced. Errors are rejected promises with Error objects; consumers must not depend on filesystem error text containing private paths.
